## 📖 معرفی پروژه

«پژوهش و جستجو» یک دستیار هوشمند پژوهشی و فارسی‌زبان است که با هدف ساده‌سازی فرایند تحقیق، گردآوری اطلاعات، بررسی منابع و تولید گزارش‌های علمی و مستند طراحی شده است.

در این سامانه، کاربر تنها کافی است موضوع موردنظر خود را وارد کند تا دستیار هوشمند به‌صورت خودکار مراحل مختلف یک پژوهش را انجام دهد.

سیستم ابتدا موضوع را تحلیل کرده و یک برنامه پژوهشی شامل پرسش‌های کلیدی تدوین می‌کند. سپس با استفاده از موتورهای جستجوی وب، منابع مرتبط را شناسایی کرده، صفحات را مطالعه می‌کند، اطلاعات استخراج‌شده را مورد بررسی و راستی‌آزمایی قرار می‌دهد و در نهایت گزارشی فارسی، ساختاریافته و منبع‌دار ارائه می‌کند.

یکی از ویژگی‌های مهم این پروژه، نمایش زنده مراحل انجام پژوهش است؛ به‌طوری‌که کاربر می‌تواند در تمام مراحل، روند پیشرفت تحقیق، وضعیت جستجو، مطالعه منابع و بررسی شواهد را مشاهده کند.

هدف اصلی این پروژه، تبدیل فرایند زمان‌بر و پراکنده پژوهش به یک فرایند هوشمند، منظم، سریع و قابل پیگیری است.

## ✨ امکانات و قابلیت‌های اصلی

- 🧠 **برنامه‌ریزی هوشمند پژوهش:** تحلیل موضوع و تبدیل آن به یک برنامه تحقیقاتی منظم.
- 🔍 **تولید زیرسؤال‌های پژوهشی:** استخراج پرسش‌های مرتبط برای بررسی دقیق‌تر موضوع.
- 🌐 **جستجوی هوشمند وب:** جستجو در اینترنت و شناسایی منابع مرتبط.
- 📚 **مطالعه صفحات وب:** دریافت محتوای صفحات و استخراج اطلاعات مهم.
- 🔎 **راستی‌آزمایی اطلاعات:** بررسی شواهد و ارزیابی اعتبار یافته‌ها.
- 📝 **تولید گزارش فارسی:** ارائه گزارش نهایی با ساختار منظم و منابع قابل بررسی.
- ⚡ **نمایش زنده مراحل:** مشاهده روند اجرای پژوهش به‌صورت مرحله‌به‌مرحله.
- 💾 **ذخیره گزارش‌ها:** نگهداری گزارش‌های نهایی در پایگاه داده SQLite.
- ⏹️ **امکان توقف پژوهش:** توقف عملیات و دریافت گزارش جزئی بر اساس یافته‌های تأییدشده موجود.
- 🔐 **محافظت در برابر SSRF:** بررسی آدرس‌ها و ریدایرکت‌ها برای جلوگیری از دسترسی به منابع داخلی و غیرمجاز.
- 🤖 **پشتیبانی از مدل‌های زبانی مختلف:** امکان استفاده از مدل‌های محلی Ollama یا APIهای سازگار با OpenAI.

## 🤖 مدل‌های هوش مصنوعی

این پروژه از دو مدل پیشنهادی برای اجرای محلی از طریق Ollama پشتیبانی می‌کند.

### ۱. Qwen3 4B

<code>qwen3:4b</code>

مدلی سبک‌تر که برای سیستم‌هایی با منابع سخت‌افزاری محدودتر مناسب است.

ویژگی‌ها:
- مصرف منابع کمتر نسبت به مدل‌های بزرگ‌تر
- مناسب برای پژوهش‌های سریع و استاندارد
- گزینه مناسب برای سیستم‌های شخصی
- امکان اجرای محلی با Ollama

دریافت مدل:

```bash
ollama pull qwen3:4b
```

تنظیم در فایل `.env`:

```env
OLLAMA_MODEL=qwen3:4b
```

### ۲. Gemma 3 12B

<code>gemma3:12b</code>

مدلی بزرگ‌تر از خانواده Gemma که برای سیستم‌های دارای منابع پردازشی و حافظه بیشتر قابل استفاده است.

ویژگی‌ها:
- ظرفیت پردازشی بیشتر نسبت به مدل ۴ میلیارد پارامتری
- گزینه‌ای برای بررسی و تحلیل موضوعات پژوهشی
- مناسب برای آزمایش و مقایسه عملکرد مدل‌های زبانی مختلف
- قابلیت اجرای محلی با Ollama

دریافت مدل:

```bash
ollama pull gemma3:12b
```

تنظیم در فایل `.env`:

```env
OLLAMA_MODEL=gemma3:12b
```

**نکته:** اجرای Gemma 3 12B به حافظه و توان پردازشی بیشتری نیاز دارد. سرعت و کیفیت پاسخ‌گویی به سخت‌افزار، تنظیمات و نوع وظیفه بستگی دارد.

### مقایسه مدل‌ها

| ویژگی | Qwen3 4B | Gemma 3 12B |
|---|---|---|
| اندازه مدل | ۴ میلیارد پارامتر | ۱۲ میلیارد پارامتر |
| منابع موردنیاز | کمتر | بیشتر |
| مناسب برای سیستم‌های ضعیف‌تر | مناسب‌تر | محدودتر |
| اجرای محلی | بله | بله |
| روش اجرا | Ollama | Ollama |

## 🚀 راهنمای نصب و راه‌اندازی

### مرحله اول: دریافت پروژه

ابتدا CMD را باز کنید و دستورهای زیر را اجرا کنید:

```bash
git clone https://github.com/a32it534/pazhuhesh_jostejoo.git
```

ورود به پوشه پروژه:

```bash
cd pazhuhesh_jostejoo
```

### مرحله دوم: نصب و دریافت Ollama

ابتدا Ollama را از وب‌سایت رسمی دریافت و نصب کنید:

https://ollama.com

سپس یکی از مدل‌های زیر را دریافت کنید.

برای Qwen3:

```bash
ollama pull qwen3:4b
```

برای Gemma 3:

```bash
ollama pull gemma3:12b
```

### مرحله سوم: ایجاد محیط مجازی Python

```bash
python -m venv .venv
```

فعال‌سازی محیط مجازی در CMD:

```cmd
.venv\Scripts\activate
```

### مرحله چهارم: نصب وابستگی‌ها

```bash
pip install -r requirements.txt
```

### مرحله پنجم: ایجاد فایل تنظیمات

```cmd
copy .env.example .env
```

اکنون فایل `.env` را باز کرده و تنظیمات موردنیاز را وارد کنید.

برای استفاده از Qwen3:

```env
OLLAMA_MODEL=qwen3:4b
```

برای استفاده از Gemma 3:

```env
OLLAMA_MODEL=gemma3:12b
```

سایر تنظیمات را مطابق نیاز پروژه و مقادیر پیش‌فرض فایل `.env.example` تنظیم کنید.

### مرحله ششم: اجرای برنامه

```bash
uvicorn app.main:app --reload
```

پس از اجرای موفق برنامه، آدرس زیر را در مرورگر باز کنید:

http://127.0.0.1:8000

برای اجرای برنامه روی پورت دیگر:

```bash
uvicorn app.main:app --port 8080
```

## 🔌 استفاده از API سازگار با OpenAI

علاوه بر اجرای محلی با Ollama، امکان استفاده از سرویس‌های API سازگار با OpenAI نیز وجود دارد.

برای مثال می‌توانید از سرویس‌هایی مانند GapGPT استفاده کنید.

در فایل `.env` تنظیمات زیر را وارد کنید:

```env
LLM_PROVIDER=openai_compatible
BASE_URL=YOUR_API_BASE_URL
API_KEY=YOUR_API_KEY
MODEL=YOUR_MODEL_NAME
```

توضیحات:

- `LLM_PROVIDER`: انتخاب ارائه‌دهنده مدل زبانی
- `BASE_URL`: آدرس پایه API
- `API_KEY`: کلید دسترسی به سرویس
- `MODEL`: نام مدل مورد استفاده

آدرس `BASE_URL` باید مطابق مستندات سرویس باشد؛ برنامه مسیر `/chat/completions` را به آن اضافه می‌کند.

پس از تغییر تنظیمات، برنامه را مجدداً اجرا کنید.

## 🔬 سطوح عمق پژوهش

برای کنترل میزان جزئیات و گستردگی تحقیق، سه سطح پژوهش در نظر گرفته شده است.

| سطح پژوهش | تعداد زیرسؤال | توضیحات |
|---|---:|---|
| سریع | ۲ | بررسی اولیه و جمع‌آوری اطلاعات اصلی |
| استاندارد | ۴ | بررسی متعادل و چندجانبه موضوع |
| عمیق | ۶ | بررسی گسترده‌تر و تحلیل دقیق‌تر موضوع |

حداکثر زمان پیش‌فرض هر پژوهش ۵ دقیقه است.

```env

```

در صورت پایان زمان تعیین‌شده یا توقف دستی، سیستم بر اساس یافته‌های تأییدشده موجود، گزارش جزئی تولید می‌کند.

## 🛠️ راهنمای رفع مشکلات رایج

### ۱. خطای اتصال به Ollama

اگر پیام «اتصال به Ollama برقرار نشد» نمایش داده شد:

- از نصب و اجرای Ollama اطمینان حاصل کنید.
- در صورت نیاز دستور زیر را اجرا کنید:

```bash
ollama serve
```

- مقدار `OLLAMA_HOST` را در تنظیمات بررسی کنید.

### ۲. خطای پیدا نشدن مدل

اگر مدل موردنظر پیدا نشد، آن را دریافت کنید:

```bash
ollama pull qwen3:4b
```

یا:

```bash
ollama pull gemma3:12b
```

همچنین مقدار `OLLAMA_MODEL` باید با نام مدل نصب‌شده یکسان باشد.

### ۳. مشکل در جستجوی وب

در برخی شبکه‌ها ممکن است دسترسی به DuckDuckGo محدود باشد.

در این شرایط می‌توانید از پراکسی با تنظیم متغیرهای زیر استفاده کنید:

```env
HTTP_PROXY=YOUR_PROXY_URL
HTTPS_PROXY=YOUR_PROXY_URL
```

همچنین امکان استفاده از یک سرویس SearXNG در دسترس وجود دارد.

آدرس آن را در تنظیم زیر قرار دهید:

```env
SEARCH_FALLBACK_URL=YOUR_SEARXNG_URL
```

### ۴. کندی پاسخ‌گویی مدل

مدل‌های زبانی بزرگ به منابع سخت‌افزاری بیشتری نیاز دارند.

برای سیستم‌های ضعیف‌تر پیشنهاد می‌شود:

- از مدل `qwen3:4b` استفاده کنید.
- سطح پژوهش را روی «سریع» قرار دهید.
- در صورت استفاده از API، از سرویس متناسب با نیاز خود استفاده کنید.
- در صورت لزوم مقدار `LLM_TIMEOUT_SECONDS` را افزایش دهید.

### ۵. پیدا نشدن شواهد کافی

اگر سیستم پیام «شواهد کافی پیدا نشد» نمایش داد:

- موضوع پژوهش را دقیق‌تر تعریف کنید.
- پرسش تحقیقاتی را محدودتر کنید.
- سطح پژوهش را روی «عمیق» قرار دهید.

سیستم برای جلوگیری از تولید اطلاعات بدون پشتوانه، از حدس‌زدن و تأیید اطلاعات فاقد شواهد خودداری می‌کند.

### ۶. خطای ۴۲۹

این خطا ممکن است زمانی رخ دهد که تعداد پژوهش‌های هم‌زمان از مقدار مجاز `MAX_CONCURRENT_JOBS` بیشتر شود.

## 🏗️ معماری و ملاحظات فنی

- هر پژوهش دارای وضعیت مستقل است.
- کش صفحات و یافته‌های هر پژوهش از سایر پژوهش‌ها جدا نگهداری می‌شود.
- اطلاعات موقت کارها در حافظه نگهداری می‌شوند.
- فقط گزارش نهایی در پایگاه داده SQLite ذخیره می‌شود.
- پایگاه داده در مسیر زیر قرار دارد:

```text
data/pazhuhesh_jostejoo.db
```

- کارها به مدت یک ساعت در حافظه باقی می‌مانند.
- یافته‌هایی که فرایند راستی‌آزمایی آن‌ها قابل پردازش نبوده است، تأییدشده محسوب نمی‌شوند و با برچسب «بررسی‌نشده» باقی می‌مانند.
- در هنگام مطالعه صفحات وب، آدرس‌های localhost، IPهای خصوصی و فایل‌های محلی مسدود می‌شوند.
- مقصد ریدایرکت‌ها نیز برای جلوگیری از دسترسی ناامن بررسی می‌شود.
