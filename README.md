## 📖 معرفی پروژه

«پژوهش و جستجو» یک دستیار پژوهشی فارسی‌زبان است که برای ساده‌سازی فرایند تحقیق، گردآوری اطلاعات، بررسی منابع و تولید گزارش‌های مستند طراحی شده است. این برنامه روی سیستم شخصی شما اجرا می‌شود.

کاربر فقط موضوع موردنظر را وارد می‌کند و دستیار مراحل پژوهش را به‌صورت خودکار انجام می‌دهد: ابتدا موضوع را تحلیل و یک برنامه پژوهشی شامل پرسش‌های کلیدی تدوین می‌کند، سپس با جستجوی وب منابع مرتبط را پیدا می‌کند، صفحات را می‌خواند، اطلاعات استخراج‌شده را راستی‌آزمایی می‌کند و در پایان یک گزارش فارسی، ساختاریافته و منبع‌دار ارائه می‌دهد.

مراحل انجام پژوهش به‌صورت زنده نمایش داده می‌شود، تا کاربر بتواند روند جستجو، مطالعه منابع و بررسی شواهد را لحظه‌به‌لحظه دنبال کند.

## ✨ امکانات و قابلیت‌های اصلی

- 🧠 **برنامه‌ریزی هوشمند پژوهش:** تحلیل موضوع و تبدیل آن به یک برنامه تحقیقاتی منظم.
- 🔍 **تولید زیرسؤال‌های پژوهشی:** استخراج پرسش‌های مرتبط برای بررسی دقیق‌تر موضوع.
- 🌐 **جستجوی وب:** جستجو و شناسایی منابع مرتبط.
- 📚 **مطالعه صفحات وب:** دریافت محتوای صفحات و استخراج اطلاعات مهم.
- 🔎 **راستی‌آزمایی اطلاعات:** بررسی شواهد و ارزیابی اعتبار یافته‌ها.
- 📝 **تولید گزارش فارسی:** گزارش نهایی با ساختار منظم و منابع قابل بررسی.
- ⚡ **نمایش زنده مراحل:** مشاهده روند اجرا به‌صورت مرحله‌به‌مرحله.
- 💾 **ذخیره گزارش‌ها:** نگهداری گزارش‌های نهایی در پایگاه داده SQLite.
- ⏹️ **امکان توقف پژوهش:** توقف عملیات و دریافت گزارش جزئی بر اساس یافته‌های تأییدشده.
- 🔐 **محافظت در برابر SSRF:** بررسی آدرس‌ها و ریدایرکت‌ها برای جلوگیری از دسترسی به منابع داخلی.
- 🤖 **پشتیبانی از مدل‌های زبانی مختلف:** مدل‌های محلی Ollama یا APIهای سازگار با OpenAI.

## 🤖 مدل‌های هوش مصنوعی

این پروژه دو مدل پیشنهادی برای اجرای محلی از طریق Ollama دارد.

### ۱. Qwen3 4B

`qwen3:4b`

مدلی سبک‌تر برای سیستم‌هایی با منابع سخت‌افزاری محدودتر.

- مصرف منابع کمتر نسبت به مدل‌های بزرگ‌تر
- مناسب برای پژوهش‌های سریع و استاندارد
- اجرای محلی با Ollama

دریافت مدل:

```bash
ollama pull qwen3:4b
```

تنظیم در فایل `.env`:

```env
OLLAMA_MODEL=qwen3:4b
```

### ۲. Gemma 3 12B

`gemma3:12b`

مدلی بزرگ‌تر برای سیستم‌هایی با حافظه و توان پردازشی بیشتر.

- ظرفیت پردازشی بیشتر نسبت به مدل ۴ میلیارد پارامتری
- مناسب برای تحلیل موضوعات پژوهشی پیچیده‌تر
- اجرای محلی با Ollama

دریافت مدل:

```bash
ollama pull gemma3:12b
```

تنظیم در فایل `.env`:

```env
OLLAMA_MODEL=gemma3:12b
```

> **نکته:** اجرای Gemma 3 12B به حافظه و توان پردازشی بیشتری نیاز دارد. سرعت و کیفیت پاسخ به سخت‌افزار، تنظیمات و نوع وظیفه بستگی دارد.

### مقایسه مدل‌ها

| ویژگی | Qwen3 4B | Gemma 3 12B |
|---|---|---|
| اندازه مدل | ۴ میلیارد پارامتر | ۱۲ میلیارد پارامتر |
| منابع موردنیاز | کمتر | بیشتر |
| مناسب برای سیستم‌های ضعیف‌تر | مناسب‌تر | محدودتر |
| اجرای محلی | بله | بله |
| روش اجرا | Ollama | Ollama |

## 🚀 راهنمای نصب و راه‌اندازی

### مرحله اول: دریافت پروژه

CMD را باز کنید و دستورهای زیر را اجرا کنید:

```bash
git clone https://github.com/a32it534/pazhuhesh_jostejoo.git
cd pazhuhesh_jostejoo
```

### مرحله دوم: نصب Ollama و دریافت مدل

ابتدا Ollama را از وب‌سایت رسمی نصب کنید: https://ollama.com

سپس یکی از مدل‌ها را دریافت کنید:

```bash
ollama pull qwen3:4b
```

یا:

```bash
ollama pull gemma3:12b
```

### مرحله سوم: ایجاد محیط مجازی Python

```bash
python -m venv .venv
```

فعال‌سازی در CMD:

```cmd
.venv\Scripts\activate
```

### مرحله چهارم: نصب وابستگی‌ها

```bash
pip install -r requirements.txt
```

### مرحله پنجم: ایجاد فایل تنظیمات

```cmd
copy .env.example .env
```

فایل `.env` را باز کنید و تنظیمات موردنیاز را وارد کنید. برای مثال:

```env
OLLAMA_MODEL=qwen3:4b
```

سایر مقادیر را مطابق نیاز خود یا بر اساس پیش‌فرض‌های `.env.example` تنظیم کنید.

### مرحله ششم: اجرای برنامه

```bash
uvicorn app.main:app --reload
```

سپس آدرس زیر را در مرورگر باز کنید:

http://127.0.0.1:8000

برای اجرا روی پورت دیگر:

```bash
uvicorn app.main:app --port 8080
```

## 🔌 استفاده از API سازگار با OpenAI

علاوه بر Ollama، می‌توانید از سرویس‌های سازگار با OpenAI (مانند GapGPT) استفاده کنید. در فایل `.env`:

```env
LLM_PROVIDER=openai_compatible
BASE_URL=YOUR_API_BASE_URL
API_KEY=YOUR_API_KEY
MODEL=YOUR_MODEL_NAME
```

- `LLM_PROVIDER`: انتخاب ارائه‌دهنده مدل زبانی
- `BASE_URL`: آدرس پایه API
- `API_KEY`: کلید دسترسی به سرویس
- `MODEL`: نام مدل موردنظر

`BASE_URL` باید مطابق مستندات سرویس باشد؛ برنامه مسیر `/chat/completions` را خودش به آن اضافه می‌کند. پس از تغییر تنظیمات، برنامه را دوباره اجرا کنید.

> کلید API را هرگز در مخزن عمومی قرار ندهید. فایل `.env` در `.gitignore` قرار دارد.

## 🩺 راهنمای رفع مشکلات رایج

### ۱. خطای اتصال به Ollama

اگر پیام «اتصال به Ollama برقرار نشد» نمایش داده شد:

- مطمئن شوید Ollama نصب و در حال اجراست.
- در صورت نیاز دستور `ollama serve` را اجرا کنید.
- مقدار `OLLAMA_HOST` را در `.env` بررسی کنید.

### ۲. خطای پیدا نشدن مدل

مدل را دریافت کنید:

```bash
ollama pull qwen3:4b
```

یا:

```bash
ollama pull gemma3:12b
```

مقدار `OLLAMA_MODEL` باید دقیقاً با نام مدل نصب‌شده یکسان باشد.

### ۳. کندی پاسخ‌گویی مدل

مدل‌های زبانی بزرگ به منابع بیشتری نیاز دارند. برای سیستم‌های ضعیف‌تر:

- از مدل `qwen3:4b` استفاده کنید.
- سطح پژوهش را روی «سریع» بگذارید.
- در صورت استفاده از API، سرویس متناسب با نیاز خود را انتخاب کنید.
- در صورت لزوم مقدار `LLM_TIMEOUT_SECONDS` را افزایش دهید.

### ۴. مشکل در جستجوی وب

اگر موتور جستجوی پیش‌فرض پاسخ نداد، می‌توانید آدرس یک سرویس SearXNG در دسترس خود را در `.env` قرار دهید:

```env
SEARCH_FALLBACK_URL=YOUR_SEARXNG_URL
```

### ۵. پیدا نشدن شواهد کافی

اگر پیام «شواهد کافی پیدا نشد» نمایش داده شد:

- موضوع پژوهش را دقیق‌تر تعریف کنید.
- پرسش را محدودتر کنید.
- سطح پژوهش را روی «عمیق» بگذارید.

سیستم برای جلوگیری از تولید اطلاعات بدون پشتوانه، از حدس‌زدن و تأیید اطلاعات فاقد شواهد خودداری می‌کند.

### ۶. خطای ۴۲۹

این خطا زمانی رخ می‌دهد که تعداد پژوهش‌های هم‌زمان از مقدار مجاز `MAX_CONCURRENT_JOBS` بیشتر شود.

## 🏗️ معماری و ملاحظات فنی

- هر پژوهش وضعیت مستقل دارد.
- کش صفحات و یافته‌های هر پژوهش از سایر پژوهش‌ها جدا نگهداری می‌شود.
- اطلاعات موقت کارها در حافظه می‌مانند (به‌مدت یک ساعت) و فقط گزارش نهایی در SQLite ذخیره می‌شود.
- مسیر پایگاه داده: `data/pazhuhesh_jostejoo.db`
- یافته‌هایی که فرایند راستی‌آزمایی‌شان قابل پردازش نبوده، تأییدشده محسوب نمی‌شوند و با برچسب «بررسی‌نشده» می‌مانند.
- هنگام مطالعه صفحات وب، آدرس‌های localhost، IPهای خصوصی و فایل‌های محلی مسدود می‌شوند و مقصد ریدایرکت‌ها نیز بررسی می‌شود.
- برنامه برای اجرای محلی طراحی شده و CORS فقط برای localhost باز است. در صورت انتشار روی سرور عمومی، حتماً احراز هویت و محدودیت دسترسی اضافه کنید.
